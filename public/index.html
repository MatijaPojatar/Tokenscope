Guide

how every feature works — click a section to expand it

Tokenscope watches your local Claude Code transcripts (~\.claude\projects) and shows what is in each session's context window, what every action cost in tokens, and where the money goes. Sessions active in the last 48 hours load automatically and new activity streams in live. Everything runs on your machine — the collector serves localhost only (port 4820) and nothing leaves it. The bundled statusline forwarder adds the exact window size, session cost, and rate-limit usage; OTLP logs (if enabled) add exact per-request cost.

Sessions

The landing page lists every session in the loaded window, newest first. Each card shows:

  • green pulsing dot — activity in the last 2 minutes (live)
  • context bar — current context vs the model's window; turns orange past 75% full, red past 90%
  • meta line — model, session cost, subagent count, ⟲n compaction count, time since last activity

Click a card (or press Enter on it) to open the session. The ← button in the session header, or the sessions item in the sidebar, returns here.

Context window gauge

The bar at the top of a session shows what occupies the context window right now, split by where the tokens came from: base (system prompt + tools + memory), conversation, docs read, code read, search, agents, other tools, attachments, output, and recache. Hover any segment for exact numbers; the legend below repeats them.

Buckets accumulate over the session's life. After a compaction shrinks the window they are scaled onto the real usage, so the bar always shows composition, not raw lifetime sums. The output segment's tooltip splits thinking / visible text / tool calls where measurable.

The header meta row shows the project path, model, cost so far, and 5-hour / 7-day rate-limit usage when the statusline forwarder reports it. Hook events flash briefly next to the title as they fire.

Time scrubber

The stacked-area strip under the gauge is the context window over time. Click or drag anywhere on it to time-travel: the gauge above shows the composition at that moment, a chip names the action the cursor points at, and the matching timeline row gets a dashed outline. Releasing scrolls the timeline to that row.

  • dashed vertical ticks — compactions
  • ⏵ live — return to now
  • clickable timestamps in the timeline jump the scrubber to that exact call

Per-action timeline

One block per prompt (turn), newest expanded by default — click a header to collapse or expand it. Each action row shows the timestamp (click to scrub), the tool call, a bar scaled to its context cost, and the tokens it added to the window.

Amber token counts mark calls that belong to an Optimize finding — click the row to focus that finding. Turns marked ⟲ are compaction summaries: the model's own record of the history that was dropped.

Base context

What is loaded before you type anything, in two groups:

  • loaded at session start — disk-scanned files (project and user CLAUDE.md, their @-imports, MEMORY.md, .claude\rules) with estimated token cost, plus a system prompt + tools remainder (the base total minus those files — transcripts don't itemize it; run /context in the terminal for the interactive breakdown)
  • injected during session — harness attachments: skill listing, agent listing, edited files re-injected after edits, todo reminders, hook output, and so on — measured where possible, size-estimated otherwise

Expand any ▸ row for the file path, size, modified time, how many sessions load it (and the total that costs), and how often this session actually read or edited it. In-context use isn't logged by the model — loads, Reads, and edits are the observable signals.

Optimize

Heuristics over the measured session; every finding carries its evidence and a concrete fix:

  • repeated searches — the same query run again and again → document the concept in a doc
  • re-read files — one file read many times → a short API doc, or split the file
  • fat docs — expensive per read → split into focused docs
  • always-loaded base files — paid every session start → trim, or move on-demand
  • harness injections — heavy hook output, full-file re-injections, reminder buildup
  • skill candidates — workflows Claude re-runs by hand → package as a skill
  • unused skill listings — listing entries paid every session for skills never used
  • agent ROI — agents returning huge results into the parent window
  • compactions and idle re-caching — session-hygiene costs

Findings are capped per kind — show n more reveals the rest. Clicking a finding highlights its calls in the timeline (and agent lists) and scrolls to them; click again to clear. Timeline rows with amber counts link back the other way.

generate plan feeds all findings plus the measured facts to your local claude CLI (headless, billed to your account) and saves a prioritized action plan to the project's .claude\context\optimize-plan-….md.

Context file

The context file button in the session header digests the whole session — prompts in order, heaviest actions, files edited and read, docs, subagents, compaction summaries — through your local claude CLI into a handoff document, saved under the project's .claude\context\session-….md. Useful for continuing work in a fresh session without re-paying the exploration.

One generation per session at a time, 5-minute timeout; cancel kills the running CLI. Billed to your own account.

Compaction

Each compaction event shows when it ran, what triggered it, and the window before → after. Expand a row for the cost: the summary plus the rebuilt context, re-paid as fresh input. Dropped history is gone for the model — earlier decisions survive only in the ⟲ summary turn.

Under the gauge you also get the compaction history and a growth forecast; the scrubber marks each event with a dashed tick.

Cache economics

Measured input-side token flows, priced at list rates when the model's price is known:

  • cache hit ratio — share of input served from the prompt cache instead of re-sent at full price
  • saved by caching — cached reads bill at 0.1× the input price
  • write premium — making content cacheable bills above input: 1.25× at 5-minute TTL, 2× at 1-hour
  • idle-gap re-writes — content re-cached after the cache expired during a pause: tokens the session had already paid for once; grouping interactions or one session per task avoids it

MCP & skills (session panel)

Per MCP server: calls, result tokens, tools used, where it's configured, and when it last ran — including calls made by subagents. Servers that were never called still load their tool schemas into base context every session (transcripts don't itemize the size). Deferred tool loads is the measured cost of ToolSearch fetching schemas on demand.

Per skill: invocations, result tokens, and its share of the skill listing paid at every session start. Unused skills are aggregated with their total standing cost. Only invocations are observable — a skill can still steer behavior from its description alone.

Docs leaderboard

Every .md this session read, ranked by tokens; the A badge means a subagent read it. Expand a doc for every individual use — time, the prompt or agent it served, tokens — and click a use to jump to that call in the timeline.

Below the list: base-loaded docs with no observed use this session — loaded and paid, never read or edited.

Agents

Each subagent runs in its own context window — only its final result returns to the parent. The summary line totals it: tokens burned in agent windows → tokens returned, with the compression ratio (burned per returned token). Delegation earns its keep when that ratio is high.

Expand an agent for its model, window size, input/output, duration, docs reads, and the full action list — each call with duration, the ~output tokens spent issuing it, and what it added to the agent's window. Amber-flagged calls link to Optimize findings here too.

Session totals

API calls, fresh input tokens, output tokens — with the output split into ~thinking, ~visible text, and ~tool calls where measurable — plus subagent calls and the tokens they burned in their own windows.

Codebase map

Every file read across the loaded window, one project at a time (switch with the chips). Bubble area = tokens spent reading the file, color = top-level directory. Only the largest ~90 files get their own bubble; the rest merge into one (n more files) bubble per directory.

  • click a bubble — details: tokens, share of project, reads, ~per read, sessions, whether agents read it
  • drag to rearrange — dropping pins the bubble in place, double-click unpins
  • files read 3+ times get a hint: a focused doc could make re-checks cheaper

Knowledge graph

build graph parses the selected project (at folder or file granularity) into modules and import edges, links your docs to the code they cover, and saves the result to .claude\context\graph.json. The status shows when it was built, at which commit, and how many commits behind it has fallen.

  • circles — modules, area = number of source files; squares — docs
  • amber halo + size boost — tokens sessions spent reading that module in the loaded window, relative to the hottest module on screen
  • solid arrows — imports, flowing top → bottom
  • dotted — a doc mentions that code area; dashed — the doc was observed in use together with it

Drag nodes, drag the background to pan, scroll to zoom. Hovering isolates a node's neighborhood; clicking shows its dependency lists and linked docs. The filter shows matching paths plus their direct import neighbors. What fits on screen is picked by structural importance — filter to reach the rest. Very large graphs use a fast banded layout; filtering restores the fully layered one.

Claude can query it too: the plugin's graph-nav skill answers structure questions (impact, dependencies, shortest chain, doc routing, hot modules) from the built graph via GET /api/graph/query — ~15 lines of context instead of grep fan-outs and file reads. Tell Claude "use the graph" or let the skill trigger on its own.

Trends

Rolled-up history that accrues from install onward and outlives the 48-hour live window:

  • tokens per day — input and output stacked; hover a column for sessions, tokens, cost, compactions
  • base context per session — is the standing cost of every session start growing?
  • projects and models — ranked by token volume with session counts and cost
  • cache economics — lifetime hit ratio, saved vs write premium

Docs & MCP across sessions

The docs and mcp pages aggregate their session panels over every loaded session and agent: every doc read anywhere (with reads, tokens, session counts), every server call and skill use — and the standing costs: docs loaded every session but never read, servers configured but never called, skills paid in the listing but never used.
